# 블로그 작성 도우미 (Manifest V3)

1. Chrome의 `chrome://extensions`에서 개발자 모드를 켜고 이 폴더를 ‘압축해제된 확장 프로그램 로드’로 추가합니다.
2. `http://localhost:3000` 웹에서 로그인하고 글을 생성한 뒤 확장 프로그램 전송을 누릅니다. 운영 주소는 팝업에 정확한 HTTPS origin을 등록하고 웹을 새로고침합니다. 운영 연결을 해제하려면 확장 프로그램을 제거하거나 Chrome 확장 설정에서 사이트 권한을 제거합니다.
3. 네이버에 직접 로그인하고 빈 새 글을 엽니다. 팝업에서 해당 탭을 선택하고 입력 버튼을 누릅니다. 클립보드는 글의 서식 있는 내용으로 교체됩니다.
4. Chrome 디버깅 권한 알림은 실제 붙여넣기 입력을 위한 것입니다. 네이버 쿠키나 웹 인증 토큰을 수집하지 않습니다. 개발자 도구와 다른 디버거가 연결되어 있으면 입력이 실패할 수 있습니다.
5. 본문 입력 후 ‘이미지 첨부 시도’를 누르면 위치 표시 뒤에서 파일 업로드를 요청합니다. 실제 새 HTTPS 이미지의 로딩·위치를 확인해야 첨부로 보고하며, 실패하면 다운로드한 이미지를 `[이미지: 식별자]` 위치에 직접 첨부하세요. 위치 표시는 확인 후 직접 지웁니다. 이미 시도한 이미지는 중복 방지를 위해 자동 재시도하지 않습니다. 이미지가 있는 글은 부분 완료 상태로 표시합니다.
6. 제목·본문·서식 DOM 비교 결과와 별개로 네이버에서 임시저장하고 다시 열어 빈 줄·공백·색상·밑줄·이미지를 확인하세요. 자동 발행과 저장·재열기 자동 검증은 구현하지 않았습니다.

입력 대상을 찾지 못하면 팝업의 ‘에디터 진단’을 누르고 ‘진단 결과 복사’로 결과를 전달하세요. 진단은 내용을 변경하지 않으며 각 프레임의 origin, 셀렉터 일치 수, 편집 가능 여부와 편집 영역 태그·클래스만 포함합니다. 글 내용, 전체 URL과 query, 네이버 ID, 쿠키, 인증 토큰은 수집하지 않습니다. 진단 결과만으로 입력·저장 성공을 판정하지 않습니다.

실제 네이버 로그인 환경에서의 호환성은 미검증입니다. 에디터 변경 시 `config.json`의 셀렉터를 갱신해야 합니다. 입력 실패 뒤에는 일부 내용이 남을 수 있습니다. 기존 내용이 있는 에디터는 덮어쓰지 않습니다. 페이지 새로고침이나 팝업 재열기로 저장된 입력 상태를 확인할 수 있습니다. 글 데이터는 `storage.session`에만 보관되어 Chrome 재시작 시 사라집니다.

선택적인 운영 HTTPS 호스트 권한은 등록한 origin에만 요청합니다. 서버 API를 직접 호출하지 않고, 로그인된 웹이 소유권 확인 API로 내보낸 문서만 전달받습니다. 웹 페이지가 손상된 경우 잘못된 글을 전달할 수 있으므로 팝업 제목과 네이버 결과를 사용자가 확인해야 합니다.

개발 검증: `node --test extension/document.test.mjs extension/lifecycle.test.mjs`

붙여넣기 키는 Windows/Linux에서 Ctrl+V, macOS에서 Command+V로 요청합니다. 플랫폼별 실제 네이버 입력 호환성은 미검증입니다. 이미지 위치 표시를 자동으로 지우면 네이버 문서 모델과 이미지 선택 상태의 영향으로 본문이 삭제될 수 있어 자동 삭제하지 않습니다. 이미지가 올라가도 표시는 사용자가 지워야 하므로 최종 상태는 부분 완료입니다.
