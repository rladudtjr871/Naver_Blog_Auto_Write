# 서식 문서 및 Chrome 확장 프로그램 계약

## 목표와 현재 검증 상태

웹에서 인증된 사용자가 생성 결과를 확인하고 명시적으로 확장 프로그램에 전송한다. 확장 프로그램은 사용자가 로그인한 네이버 스마트에디터 ONE에 내용을 입력하며 자동 발행하지 않는다. Python/Selenium은 필수 조건에서 제외하되 기존 자산을 삭제하지 않는다.

이 문서는 구현 계약이다. 실제 네이버 입력, 혼합 서식 유지, 임시저장 후 재열기는 네이버 로그인 환경에서 별도 검증해야 한다. 화면 입력이나 요청 접수만으로 저장 완료를 표시하지 않는다.

## 문서 계약

AI 입력은 항목별 의미를 공통 프롬프트에 명시한다. `topic`은 사용자가 정한 글 전체의 주제·전개 흐름·구성·작성 요청이며, 앞의 `[카테고리: ...]`는 카테고리다. `place`는 글에서 다루는 장소다. `examples`는 같은 말투·문장 길이·문단 구성·도입과 마무리·이모지·강조 패턴으로 새 글을 써 달라는 스타일 요구다. `images[].filename`은 이미지 설명으로 활용하며 실제 시각 정보·카테고리·장소·주제를 함께 참고해 묘사와 배치를 결정한다. 명시적인 topic 요구를 추론한 예시 스타일보다 우선하고, 예시의 사실이나 파일명만으로 확인되지 않은 정보를 본문에 단정하지 않는다.

```ts
type TextColor = '#E53935' | '#1565C0' | '#00875A' | '#6A1B9A';
type TextSegment = {
  text: string;
  bold?: boolean;
  underline?: boolean;
  color?: TextColor;
};
type BlogDocument = {
  version: 1;
  title: string;
  blocks: Array<
    | { type: 'paragraph'; segments: TextSegment[] }
    | { type: 'image'; imageId: string }
  >;
};
```

- 문단과 구간 순서, 공백, 빈 문단을 보존한다. 빈 문단은 빈 문자열 구간으로 표현할 수 있다. 렌더링·전송에서 `trim()`이나 빈 줄 필터를 적용하지 않는다.
- 이미지 참조는 해당 글의 DB `Image.id`다. 다른 글의 이미지나 존재하지 않는 이미지는 허용하지 않는다. 파일명이나 네이버 생성 ID를 참조 키로 사용하지 않는다.
- 서버가 AI 결과의 버전·블록·서식·색상·이미지 참조를 검증한 뒤 저장한다. 잘못된 구조화 결과를 조용히 일반 텍스트로 낮추지 않고 생성 오류로 표시한다.
- AI는 네이버 HTML이나 스크립트를 생성하지 않는다. HTML은 문서의 텍스트를 이스케이프하고 허용한 문단·굵게·밑줄·색상 표현만 사용해 변환한다. 웹과 확장 프로그램이 같은 문서를 소비한다.

## 저장과 API 호환

- `BlogPost.document`에 nullable JSONB를 추가한다. Prisma에는 nullable `Json` 필드를 추가하고 기존 Supabase 사용 방식을 유지한다. 배포 시 제공된 SQL 마이그레이션을 먼저 적용한다.
- 기존 `title`, `content`는 유지한다. 새 글은 검증된 문서와 그 일반 텍스트 표현을 함께 저장한다. 일반 텍스트는 호환용이며 서식 원본은 `document`다.
- 기존 인증·소유권 검사를 유지한 `GET /api/posts/[id]` 상세 응답에 `document`를 추가한다. 목록 응답에 전체 이미지·문서를 불필요하게 중복하지 않는다.
- `document`가 null인 기존 글은 `title`과 `content`의 줄바꿈을 보존해 서식 없는 v1 문서로 읽는다. 기존 이미지 위치 표식은 일치하는 해당 글 이미지로 연결하고, 해석할 수 없는 표식은 텍스트로 보존한다. 기존 DB 행을 일괄 수정하지 않는다.
- 신규 생성 작업은 서버리스 응답 후 버려지는 Promise에 의존하지 않도록 플랫폼이 지원하는 실행 수명 수단을 사용한다. 실행 시간 제한에 따른 실패는 글 상태에 반영한다.

## 웹과 확장 프로그램 전달·보안

- 웹이 로그인 사용자의 API로 글 상세를 가져온 다음, 전송 버튼을 누를 때 문서와 해당 글의 이미지 데이터를 content bridge에 전달한다. 확장 프로그램에는 인증 토큰·AI Key·네이버 쿠키를 전달하지 않는다.
- bridge는 동일 window의 정확한 origin과 메시지 형식·버전을 검사한다. 확장 프로그램은 등록한 웹 origin의 content script 메시지만 받는다. 전달 원본은 확장이 다시 인증한 서버 응답이 아니므로 구조·크기·이미지 데이터도 검증한다.
- 개발 origin 기본값은 `http://localhost:3000`이다. 운영 origin은 팝업에서 정확한 HTTPS origin을 등록하고 사용자 호스트 권한 허용 후 동적 content script를 등록한다. 임의 사이트 전체에 bridge를 노출하지 않는다.
- 전달된 글은 `chrome.storage.session`에 일시 보관하고 사용자에게 글 제목과 입력 대상을 확인시킨다. 네이버 로그인은 사용자가 브라우저에서 한다. 네이버 세션을 읽거나 외부에 전송하지 않는다.
- 자동화는 사용자 입력 동작에서만 시작한다. `chrome.debugger`를 사용할 경우 권한 목적을 설명하고 네이버 대상 탭에만 연결하며 종료·실패 시 해제한다. 합성 `KeyboardEvent` 반복으로 실제 입력을 대체하지 않는다.
- iframe·편집 영역·포커스·선택 범위를 확인하고 셀렉터를 확장 프로그램 `config.json`에서 관리한다. 비어 있지 않은 에디터는 자동 덮어쓰기하지 않는다. 부분 입력 후 재시도는 중복 위험을 알리고 사용자가 정리한 뒤 수행한다.
- HTML 붙여넣기를 우선 구현·실험하되 실제 호환성은 미확정이다. 필요한 서식이 유지되지 않으면 사용자에게 알리고 에디터 도구 적용을 후속 검토한다.
- 이미지는 별도 업로드 단계로 처리한다. 이미지 업로드 완료를 DOM에서 확인하지 못하면 부분 완료로 표시하고 수동 첨부 수단을 제공한다. 텍스트 자리표시자를 실제 첨부 성공으로 표시하지 않는다.

## 상태와 수용 기준

생성 완료 → 확장 수신 → 에디터 입력 진행 → 입력 검증 또는 부분 실패를 구분한다. 저장 검증은 자동 입력과 별도이며 네이버 임시저장·재열기 확인 전에는 완료로 보고하지 않는다.

자동 검증은 문서 검증·악성 텍스트 이스케이프·legacy 빈 줄 보존·이미지 참조·origin 및 메시지 거부·혼합 서식 렌더링을 다룬다. 수동 수용 시나리오는 다음과 같다.

1. 한글·이모지·앞뒤 공백·연속 빈 줄·굵게/색상/밑줄 혼합 구절이 있는 글을 생성한다.
2. 웹 미리보기와 확장 프로그램에 수신한 제목·본문·이미지 순서를 비교한다.
3. 로그인한 네이버의 빈 에디터에 입력하고 제목·본문·빈 줄·서식·실제 이미지 첨부를 비교한다.
4. 네이버에서 임시저장 후 재열어 내용과 서식이 유지되는지 확인한다. 최종 발행은 사용자가 수행한다.
5. 로그인 필요, iframe 탐색 실패, 권한 거부, 이미지 일부 실패, 기존 본문 존재, 중간 실패 후 재시도에서 명확한 상태와 중복 방지를 확인한다.

네이버 계정 로그인 및 실제 저장 검증, 운영 웹 origin 권한, DB 마이그레이션 실행이 사용자 환경에서 필요한 작업이다. 이미 등록한 AI Key를 재발급할 필요는 없다. 새 외부 유료 서비스 도입은 기본 요구사항이 아니다.
