# 공통 개발 규칙

1. **안전성 최우선:** 네이버 계정·세션·쿠키, AI API Key, 인증 토큰을 로그·응답·패키지에 노출하지 않는다. 서버 비밀은 환경 변수로 관리하고 암호화 키 누락을 고정 기본 키로 숨기지 않는다.

2. **점진적 모듈화:** 웹 프론트엔드, API, AI 생성·문서 변환, 확장 프로그램, DB를 분리하고 작은 단위로 구현·검증한다.

3. **DOM 변화 대응:** 확장 프로그램 DOM 셀렉터는 `config.json`으로 분리한다. iframe과 편집 영역을 확인하고 셀렉터 실패를 명확히 보고한다. 네이버 생성형 ID를 고정하지 않는다.

4. **교차 검증:** 개발 결과는 QAT 기준으로 검토·테스트한다. 독립 검토가 가능하면 QAT에 위임한다. 불가능하면 검토 범위를 보고하고 독립 검증을 받았다고 주장하지 않는다.

5. **제품 목표:** 웹에서 만든 글을 Manifest V3 확장 프로그램으로 전송한다. 제목·텍스트·빈 줄·문단 순서·이미지 위치와 굵게·글자색·밑줄을 보존한다. 자동 발행은 기본 범위에서 제외한다.

6. **문서 원본:** AI는 구조화 문서를 생성하고 웹 미리보기와 확장 프로그램이 이를 공유한다. 네이버 내부 HTML을 데이터 계약으로 삼지 않는다. 기존 일반 텍스트 글의 읽기 호환을 유지한다.

7. **입력·저장 검증:** 합성 키 이벤트, HTML 변경, 요청 성공만으로 성공을 판정하지 않는다. 실제 편집 결과와 임시저장 후 재열기로 판정한다. 미지원 서식과 부분 실패를 숨기지 않는다.

8. **최소 권한:** 서버에서 인증·소유권을 검사한다. 확장 프로그램 권한·호스트·메시지 발신자를 제한한다. HTML 변환에서 텍스트 이스케이프와 허용 태그·스타일·이미지 출처 검증을 적용한다.

9. **현재와 목표 구분:** Python/Selenium과 Base64 저장은 기존 구현이다. 확장 프로그램·서식 문서·다른 이미지 저장소를 구현 완료로 표현하지 않는다. 별도 요청 없이 기존 자산을 삭제하지 않는다.

10. **실행 수명:** 폴링은 상태 조회다. 서버리스 작업 지속은 별도로 보장하며 배포 환경의 실제 제한을 확인한다.
