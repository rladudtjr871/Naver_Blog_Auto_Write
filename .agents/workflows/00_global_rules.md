# 공통 목표와 아키텍처

## 데이터 흐름

웹 입력 → 인증된 API → AI 구조화 문서 생성·검증·저장 → 같은 문서의 웹 미리보기 → 인증된 확장 프로그램 조회 → 네이버 편집 영역 입력 → 임시저장·재열기 검증 → 사용자 최종 발행.

내용과 서식을 함께 옮긴다. 문단·빈 줄·이미지 위치와 구간별 굵게·글자색·밑줄을 표현한다. 네이버 DOM 복제나 한 글자씩 타이핑하는 방식을 필수 구조로 고정하지 않는다. 자동 발행은 기본 범위에서 제외한다.

## 현재 상태

웹은 Next.js와 Supabase SDK를 사용하고 AI 결과는 일반 텍스트다. 로컬 전송은 Python/Selenium, 이미지는 Base64 Data URL 저장 방식이다. 확장 프로그램은 새로 구현할 목표다. 기존 PC 자산 제거·저장소 이전은 별도 작업이다.

## 협업 순서

1. PMA: 요구사항, 문서 데이터 계약·기존 글 호환, API·DB 변경 범위, 수용 기준을 확정한다.
2. UXD·FSD: 같은 문서의 미리보기와 전송 UI를 설계하고 짧은 문단으로 실제 에디터의 입력·서식 유지를 검증한다.
3. FSD: 검증된 방법으로 웹·API·확장 프로그램을 구현한다. iframe, 포커스·선택 범위, 메시지, 이미지 업로드와 실패 복구를 처리한다.
4. QAT: 코드 검토와 실제 네이버 입력·임시저장·재열기로 보존 여부를 확인한다. 실패는 FSD로 돌린다.
5. DVO: 검증 범위를 확인하고 환경 설정·권한·패키징·배포·설치 안내를 정리한다.

## 인계와 판정

파일 경로, 변경 요약, 검증 방법·결과, 남은 문제를 인계한다. 요청 접수와 입력 완료, 저장 검증 완료를 구분한다. 네이버 접속 환경이 없으면 실제 동작은 미검증으로 기록한다. 특정 `/browser` 도구가 있다고 가정하지 않는다. 역할별 검토는 루트 지침을 따른다.

세션·AI Key를 보호하고 사용자 소유권을 확인한다. 상세 공통 규칙은 `../rules/stack.md`, 역할별 규칙은 같은 폴더의 각 문서를 따른다.
