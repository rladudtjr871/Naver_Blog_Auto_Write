# PMA: 기획과 데이터 계약

## 책임

웹 생성·서식 미리보기·확장 프로그램 전송의 요구사항, 데이터 계약, DB·API 변경과 백로그를 정의한다. 자동 발행은 기본 범위에서 제외한다.

## 설계 항목

- 입력은 카테고리, 주제·가이드, 참고 글, 장소, 이미지다. 기존 사용자·API Key·저장 내역 기능을 고려한다.
- 버전이 있는 구조화 문서로 제목, 문단, 텍스트 구간별 굵게·글자색·밑줄, 이미지 식별자·배치 순서를 표현한다. 빈 문단도 보존한다.
- 웹 미리보기와 확장 프로그램이 같은 계약을 사용한다. HTML은 변환 결과이며 네이버 클래스·생성형 ID는 계약에 포함하지 않는다.
- 기존 일반 텍스트는 줄바꿈·빈 줄을 보존한 서식 없는 문서로 읽는다. 구체적인 타입·API 입출력과 마이그레이션 필요 여부, 구버전 글·확장 프로그램 처리를 구현 전에 확정한다.
- 인증된 글 조회, 소유권, 문서 버전 검증, 생성·전송 상태 구분을 반영한다. POST ID를 인증 수단으로 취급하지 않는다.
- `User`, `ApiKey`, `BlogPost`, `ReferencePost`, `Image`, `DefaultReference`의 실제 DB·Prisma·SQL 차이를 확인한다. ORM·이미지 저장소 교체를 전제로 삼지 않는다.
- 입력 방식은 FSD의 실제 에디터 검증 결과로 확정한다. 미지원 서식은 알리고 조용히 일반 텍스트로 낮추지 않는다.

## 수용 기준과 인계

내용·빈 줄·문단·이미지 순서·혼합 서식이 미리보기와 네이버에서 일치하고 임시저장 후 재열기에서도 유지되어야 한다. 기존 글 조회, 인증 실패, 부분 실패·중복 삽입 방지 기준을 포함한다.

설계 산출물 경로, 데이터·API 계약, 호환 전략, 수용 기준, 남은 기술 검증을 UXD·FSD에 전달한다. 현재 PC 구현과 목표 확장 프로그램을 구분한다.
