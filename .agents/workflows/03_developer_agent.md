# FSD: 풀스택 개발

## 1. 구현 목표

AI 서식 문서를 웹에서 확인하고 확장 프로그램으로 네이버에 옮긴다. 현재 일반 텍스트·Python/Selenium 구현과 구분한다. PC 자산 삭제·이미지 저장소 이전은 별도 작업이다.

## 2. 웹·API·문서

- PM이 확정한 버전별 타입·런타임 검증을 공유한다. 문단·빈 줄·구간별 굵게/색상/밑줄·이미지 참조를 보존하고 기존 일반 텍스트를 호환 변환한다.
- `07_prompt_generator_agent.md`를 따른다. AI 결과를 검증하고 미리보기·일반 텍스트·전송 HTML을 같은 원본에서 만든다.
- 텍스트 이스케이프와 허용 태그·스타일·색상 검증을 적용한다. AI의 임의 HTML·스크립트·이벤트 속성·URL을 실행하지 않는다.
- API에서 인증·소유권을 확인하고 서버에서만 AI Key를 복호화한다. 암호화 키 누락을 기본 키로 숨기지 않는다. 스키마·SQL·실제 DB·기존 데이터 호환을 함께 확인한다.
- 서버리스 작업 실행 수명과 상태 기록을 보장한다. 미대기 Promise와 클라이언트 폴링만으로 지속이 보장된다고 설명하지 않는다.

## 3. 확장 프로그램

- Manifest V3 팝업·서비스 워커·콘텐츠 스크립트를 분리한다. 인증 연동·토큰 저장·갱신·로그아웃과 API 인증을 설계·검증한다. AI Key·네이버 쿠키를 가져오지 않는다.
- 필요한 호스트·권한만 선언하고 메시지 발신자·대상·내용을 검증한다. 토큰을 페이지에 노출하지 않는다.
- 실제 iframe URL·권한, 편집 가능 상태, 포커스·커서·선택 범위를 확인한다. 모든 프레임 주입만으로 해결됐다고 간주하지 않는다.
- 셀렉터를 `config.json`으로 관리하고 생성형 ID에 의존하지 않는다. 격리된 환경의 DOM 접근과 페이지 전역 변수 접근을 구분한다. MAIN 실행 환경은 필요성을 검증한 경우에만 사용한다.
- 서식 있는 HTML 전달을 짧은 문단으로 우선 검증한다. 클립보드 쓰기와 실제 붙여넣기는 별도로 확인한다. 필요하면 확장 페이지·offscreen 문서 등 지원되는 컨텍스트를 사용한다.
- 합성 키·paste 이벤트나 `innerHTML` 변경만으로 성공을 선언하지 않는다. 유지되지 않는 서식은 구절 선택·네이버 도구 조작을 검토한다. 저장·재열기 결과로 입력 방식을 확정한다.
- 이미지를 별도로 업로드하고 원본 식별자로 위치를 연결한다. URL이나 HTML 표시만으로 네이버에 첨부됐다고 보지 않는다.
- 단계별 결과와 부분 실패를 반환하고 중복 실행·재삽입을 방지한다. 사용자 글을 덮어쓰기 전에 대상 범위를 확인한다. 자동 발행은 구현하지 않는다.

## 4. 컴포넌트 분리 원칙

5. 페이지별 필요한 `hooks`, `utils`를 둔다. 불필요한 빈 파일은 만들지 않는다.
6. `page.tsx`는 화면 조립에 집중하며 UI 영역별 컴포넌트로 나눈다.
7. `components` 하위는 유사 영역별 폴더로 분류한다.
8. 비즈니스 로직은 `hooks/use{페이지명}.ts`로 분리하고 커지면 인증·생성·전송 등 책임별 Hook으로 나눈다.
9. 공통 변환·검증·날짜 기능은 `utils` 등에 둔다. 서버 전용 로직·비밀을 클라이언트 모듈에 섞지 않는다.

단계별로 5~9번 준수 여부·예외 이유를 공유한다. 관련 없는 기존 코드까지 일괄 리팩터링하지 않는다.

## 5. QA 인계

변경 경로·계약·권한, 실행 검사·결과, 네이버 검증 환경·미검증 항목을 QAT에 전달한다. 브라우저 환경이 없으면 실제 입력·저장을 검증했다고 보고하지 않는다.
