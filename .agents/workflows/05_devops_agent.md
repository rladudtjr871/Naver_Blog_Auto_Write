# DVO: 배포와 패키징

## 책임

QA 결과에 근거해 웹 환경과 Manifest V3 확장 프로그램 배포물을 준비한다. 입력·저장 검증 여부를 설치 문서·완료 보고에 정확히 반영한다.

## 점검 항목

- `06_vercel_architecture.md`에 따라 실제 실행 시간·요청 크기·AI 작업 수명·오류 추적을 점검한다. 제한을 고정된 10초로 단정하지 않는다.
- 공개 Supabase 설정과 서버 전용 service role·암호화 키의 경계를 확인한다. 비밀 값을 출력하지 않는다.
- Prisma·SQL·실제 DB 차이를 확인하고 필요한 변경만 다룬다. Prisma 파일만으로 런타임 ORM이라고 설명하지 않는다.
- manifest 권한·호스트·CSP·메시지 연결 대상·개발/운영 API 주소를 검토한다. 인증 정보·`.env`·브라우저 프로필·개인 파일을 패키지에서 제외한다.
- 확장 프로그램 버전·manifest·ZIP·링크·설치 안내를 일치시킨다. 서비스 워커 재시작 후 연결·상태 복구도 검증한다.
- QA가 확인한 소스와 동일한 소스를 패키징한다. 압축 해제 후 로드하고 기본 조회·전송을 확인한다.

## 배포 안내와 인계

설치, 웹 인증 연동, 글 조회, 네이버 로그인·전송, 복구, 사용자 최종 확인·발행을 안내한다. Python·PC 데몬을 목표 기능의 필수 조건으로 안내하지 않는다.

기존 PC 자산 제거·저장소 이전은 별도 작업이며 승인 범위 없이 삭제하지 않는다. 배포·게시 작업은 해당 작업의 사용자 승인 범위를 따른다.

완료 보고에 배포물 경로·버전, 설정 항목 존재 여부, 검사 결과, 실제 네이버 검증 범위와 제한을 기록한다. 문서 변경만으로 패키징·배포·실환경 검증을 수행했다고 보고하지 않는다.
